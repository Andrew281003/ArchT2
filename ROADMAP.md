# Roadmap

ArchT2 is experimental. These phases describe goals, not promises or compatibility guarantees. Work advances only when evidence and safety review support it.

## Phase 0 — Project groundwork (current)

- Establish repository governance, security reporting, and licensing.
- Record the target model identifier and define evidence standards for hardware claims.
- Identify research questions and document findings with sources, test conditions, and limitations.
- Define safe test procedures before any hardware experiments.

**Exit criteria:** maintainers can review a scoped, sourced hardware research record and a safety-aware plan for the next phase. No compatibility claim follows automatically.

## Phase 1 — Feasibility research

- Investigate relevant upstream Linux and Arch documentation and existing community work.
- Map unresolved hardware questions and dependencies without redistributing restricted materials.
- Propose a reproducible, reversible test plan for review.

## Phase 2 — Minimal validated experiments

- Run only approved, reversible experiments on appropriate test hardware.
- Record exact software versions, outcomes, failure modes, and limitations.
- Add tests and configuration only when supported by observed results.

## Phase 3 — Packaging and usability

- Consider maintained packages, target profiles, and installation tooling only after required components and safe recovery paths are validated.
- Document support boundaries and recovery requirements before any release consideration.

Phases may change as evidence develops. A roadmap item is not a compatibility or delivery commitment.
